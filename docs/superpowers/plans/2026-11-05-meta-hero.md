# Meta Hero: implementation plan

Spec: this document (Intent and Global Constraints are binding).
Branch: `feat/meta-hero`, based on `docs/live-deployment` (PR #2).

## Intent

AquaSentinal is judged by Meta judges on Impact (30%), Use of Meta AI tooling (25%), Technical depth (20%) and Demo (25%).
The owner wants the Meta Model API to be the visible hero of the product, credits spent only where they visibly matter, and a submission that feels like the need of the hour.
The owner will add a `MODEL_API_KEY` soon; until then every live path is built against the documented API shapes and tested with `httpx.MockTransport`, exactly like the existing `backend/tests/test_meta.py`.
There is no hardware: the digital twin stays the plant, and a phone or laptop camera on the https site is the only real-world input.

Winning thesis:

1. Judges must see real Meta calls, not claims: every live call is logged, recorded once by the owner, and replayed to judges at zero cost with an honest "RECORDED LIVE RUN" tag.
2. Meta models do physical-world work in a chain (voice, agentic planning with tools, segmentation, grounded Q&A, work orders), each output feeding the next.
3. Credit discipline is shown as engineering (cache, cascade gating, budget cap, passcode lock), not hidden.
4. Impact is concrete: Indian aquaculture and water infrastructure operators, Hindi voice and reports, actionable work orders, a measured SAM-in-murky-water benchmark.

## Global Constraints

- **Honesty (non-negotiable):** a provider or LIVE label is derived from logged state only. `LIVE_META` appears only for a successful request to the Meta endpoint recorded in `model_executions`. A cache hit is labelled `CACHED_LIVE` and points at the original execution id. Recorded bundles are labelled `RECORDED LIVE RUN` with their recording date and trace ids. Offline output is labelled with its offline provider. Nothing synthetic ships in `public/`; synthetic test bundles live under `e2e/fixtures/` and are labelled `SYNTHETIC`.
- **No invented numbers:** market or impact figures appear only with a cited source URL. Benchmarks and metrics not yet measured render as `NOT RUN` with the reason.
- **Credits:** a Meta call happens only on an explicit operator action (plan, transcribe, ask, shutter, generate) or a mission capture that passes the cascade gate. Identical requests are served from the response cache. A process-wide USD budget cap refuses calls before spending. When `AQUA_LIVE_PASSCODE` is set, Meta-calling routes require header `X-Aqua-Passcode`; without it they behave as if no key is set (labelled `LIVE LOCKED`).
- **Secrets:** the key and passcode never reach the browser bundle, logs, reprs, exceptions or bundles. Passcode comparison uses `hmac.compare_digest`.
- **Existing patterns:** backend Meta calls go through `backend/app/meta/client.py` (`MetaClient`, execution records, `UsageTracker` prices). Frontend API calls go through `lib/api/client.ts`; state through `lib/store/mission.ts` or `lib/sim/store.ts`; design tokens from `lib/theme.ts` and `app/globals.css`; motion through `lib/animations/` (single GSAP registration, `useGsap`, honours reduced motion); reuse `components/ui/shared.tsx` primitives.
- **Look and feel:** sleek, dark, instrument-grade, consistent with the current mission control (monospace labels, thin rules, teal and amber accents). Every new view works from 320 px to 2560 px without horizontal scroll and has keyboard access and visible focus.
- **Repo rules (AGENTS.md):** never use the em dash character; no agent co-author trailer in commit messages; in long Markdown put each sentence on its own line.
- **Quality gates for every task:** `npm run typecheck`, `npm run lint`, `npm run sim:check`, `npm run backend:test`, plus the e2e specs touching the changed UI (`npx playwright test e2e/<spec>`; the full suite takes about 15 minutes, run it only in Task 12). New logic gets tests. Do not loosen existing tests; update visual baselines only for intentional changes and say which.
- **Commits:** conventional commit subjects (`feat(scope): ...`), small and focused, on `feat/meta-hero`. Do not push.

## Task 1: Credit governor and live lock (backend)

Files: `backend/app/meta/client.py`, new `backend/app/meta/governor.py`, `backend/app/db.py`, `backend/app/config.py`, `backend/app/main.py`, `backend/app/perception/pipeline.py`, `.env.example`, `render.yaml`, tests in `backend/tests/test_governor.py`.

1. Settings: `AQUA_META_BUDGET_USD` (float, default `1.00`) and `AQUA_LIVE_PASSCODE` (string, default empty). Expose in `settings.public()` only `budgetUsd` and `liveLockEnabled` (bool), never the passcode.
2. Budget: before each Meta request, estimate its worst-case cost with the existing price constants and refuse with a new `MetaBudgetExceeded(MetaAPIError)` (HTTP 402, code `budget_exceeded`) when `spent + estimate > budget`. Spent is the sum of `cost_usd` over LIVE_META executions persisted in SQLite, so it survives restarts on a persistent disk.
3. Response cache: SQLite table `meta_cache(key TEXT PRIMARY KEY, model TEXT, execution_id TEXT, response TEXT, created_at REAL)`. Key is sha256 over the model id and the canonical JSON request with any image or audio bytes replaced by their sha256. Apply to `chat` and `responses_stream_text` and `multipart`. A hit returns the stored response without a network call, records an execution with classification `CACHED_LIVE`, `costUsd: 0` and `cachedFrom: <original execution id>`. Only successful live responses are cached; mocked transports cache under the same rules so tests can prove it.
4. Cascade gate in the perception pipeline: call SAM for a capture only if the frame quality is usable, the frame is not a duplicate (existing `is_duplicate`), and the capture is a waypoint capture or a re-observation of a candidate. Each skipped call increments a `saved` counter with a reason (`duplicate`, `unusable_quality`, `not_candidate`, `cache_hit`, `budget`). Keep the existing per-mission request budgets.
5. Live lock: a FastAPI dependency `live_access(request) -> bool` returns true when no passcode is configured or the `X-Aqua-Passcode` header matches. Routes that would call Meta pass this into the services; when false they take the existing no-key path, with the provider label `LIVE_LOCKED` where a provider is reported, and `/api/voice/transcribe` returns 403 `{"error": "live mode locked"}`.
6. `GET /api/system/status` gains `credits: {budgetUsd, spentUsd, remainingUsd, liveCalls, cachedCalls, saved: {total, byReason}}` and `live: {lockEnabled, unlocked}` (unlocked computed from the request header). Add `POST /api/system/unlock` that returns `{unlocked: bool}` for a passcode in the body, rate limited to 10 attempts per minute per client IP in memory.
7. Tests: budget refusal before any transport call; cache hit returns identical payload, logs `CACHED_LIVE`, makes zero transport calls; cache key changes when image bytes change; cascade skips duplicates and counts reasons; passcode required when set, wrong passcode refused, constant-time compare used; status shape; secrets never in `settings.public()` or reprs.

## Task 2: Credit meter and live unlock (frontend)

Files: `lib/api/client.ts`, `lib/store/mission.ts`, `components/ui/LabUI.tsx`, new `components/ui/credits.tsx`, e2e `e2e/credits.spec.ts`.

1. Header chip `CREDITS $0.042 / $1.00` with a thin progress bar; tooltip and click-open popover show live calls, cached calls, saved calls by reason, and the honest note "estimate from Meta list prices". Grey when no key, amber above 80 percent, red when exhausted.
2. When `live.lockEnabled && !live.unlocked`, the AI chip shows `LIVE LOCKED` with a lock icon; clicking opens an unlock dialog (passcode field, submit to `/api/system/unlock`). On success the passcode is kept in `sessionStorage` (wrapped in try/catch) and sent as `X-Aqua-Passcode` on every API request from `lib/api/client.ts`. Never put it in the URL or localStorage.
3. e2e: with the backend in the default e2e config the chip shows the no-key state; mock `/api/system/status` with `page.route` to cover amber, exhausted and locked states and the unlock flow.

## Task 3: Hindi and English for voice and AI output

4. Offline paths stay English and the UI shows `Hindi needs Meta models` next to offline output when `hi` is selected. Do not machine-translate templates.
5. Tests: request bodies carry the right `languageBias` and the language instruction; offline label shown.

## Task 4: Ask the Inspector

Files: new `backend/app/mission/ask.py`, `backend/app/mission/tools.py`, `backend/app/main.py`, `backend/app/schemas.py`, new `components/ui/ask.tsx`, `components/ui/report.tsx`, `lib/api/client.ts`, `lib/store/mission.ts`, tests, e2e `e2e/ask.spec.ts`.

1. `POST /api/inspection/{missionId}/ask` with `{question, language}` returns `{answer, citations: [{captureId, x, y, label}], toolCalls: [...], provider, model, executionIds}`.
2. Live: Muse Spark tool loop (max 3 turns, bounded `max_tokens`) with read-only tools registered in a new ASK phase of the existing `ToolRegistry`: `list_observations(label?)`, `get_capture(captureId)`, `get_track(trackId)`, `get_mission_summary()`, `compare_with_previous_mission()`. The system prompt requires every factual claim to cite capture ids returned by tools; citations not returned by a tool are dropped server-side.
3. Offline: a deterministic intent matcher for where, how many, what, and confidence questions over the stored records, labelled `OFFLINE_RECORDS_QUERY`; anything else answers that free-form questions need Meta models.
4. Goes through the governor (cache, budget, lock).
5. UI: in scene 07 under the report, a sleek "Ask the inspector" panel: text field plus push-to-talk (reuse the existing voice capture), three suggested questions, answer with streaming-style reveal (animation only, the response is not streamed), citation chips with frame thumbnails. Clicking a citation moves the twin's selection and camera to that asset (reuse the existing asset selection and camera preset mechanism). Provider badge per answer.
6. Tests: tool allowlist enforced, uncited ids dropped, offline intents, e2e of the offline path and of a mocked live answer via `page.route`.

## Task 5: Work orders

Files: new `backend/app/mission/workorders.py`, `backend/app/main.py`, `backend/app/schemas.py`, `components/ui/report.tsx` (or new `components/ui/workorders.tsx`), `app/globals.css` print rules, tests.

1. `POST /api/inspection/{missionId}/work-orders` with `{language}` returns `{orders: [{id, priority: "P1"|"P2"|"P3", title, location: {x, y}, evidence: [captureId], action, effort: "S"|"M"|"L", rationale}], provider}`.
2. Live: Muse Spark structured output (`response_format` json_schema) grounded only in the mission's anomaly candidates and observations; orders citing unknown capture ids are dropped. Cached via the governor.
3. Offline: rule table from anomaly class to order (`loose_cable` P1 secure and re-route the cable, `foreign_object` P2 remove the object, others P3 inspect), labelled `OFFLINE_RULES`.
4. UI: work order cards in the report with priority colour, location, evidence thumbnails and a "Print work orders" button that uses `window.print()` with a clean print stylesheet (white paper, no 3D canvas, page breaks per order).
5. Tests: schema validation, unknown evidence dropped, offline rules, e2e that the cards render and the print button exists.

## Task 6: Real water camera

Files: new `components/ui/realcam.tsx`, `components/ui/scenes.tsx` or `LabUI.tsx` entry point, `lib/api/client.ts`, `backend/app/main.py`, `backend/app/meta/sam.py` (reuse), tests, e2e `e2e/realcam.spec.ts`.

1. A "Real water" panel reachable from the header (camera icon) on every screen size. It opens the device camera with `getUserMedia({video: {facingMode: "environment"}})` (https or localhost only; otherwise show why) and offers an image file upload as fallback.
2. Shutter captures one frame, downscales to max 1024 px on the long side, JPEG quality 0.85, and posts multipart `frame` plus `prompt` to new `POST /api/ai/segment-image` (4 MB cap, same validation as captures). Prompt chips: `cable`, `plastic bottle`, `rope`, `pipe`, plus free text.
3. Backend runs one SAM 3.1 request per prompt (max 2 prompts per shutter) through the governor and returns polygons, boxes and confidences; result overlay drawn on the still frame with the mission-control mask style; latency, cost and provider badge shown.
4. No key or locked: the shutter still works and the panel says `SAM 3.1 needs the Meta key` with no fake overlay.
5. Permissions-Policy in `vercel.json` must allow `camera=(self)`.
6. Tests: route validation and caps, governor applied; e2e with a fake camera (`--use-fake-device-for-media-stream`) and a mocked segment response via `page.route`.

## Task 7: Murk benchmark

Files: `backend/app/evaluation.py`, `shared/fixtures/eval/` (new twin frames and ID masks), new `e2e/benchmark-frames.spec.ts` or `scripts/` capture helper, new `components/ui/benchmark.tsx`, `components/ui/intelligence.tsx`.

1. Capture twin frames and their ID passes of the same waypoint at five turbidity levels (0.10, 0.30, 0.50, 0.65, 0.80) using the product's own renderer (a Playwright helper is fine), stored under `shared/fixtures/eval/murk/` with a manifest.
2. `python -m app.evaluation --murk` runs SAM 3.1 on each frame for the visible target phrases (at most 2 phrases per frame, budget guard, cache), scores IoU against the ID pass with the existing scorer, and writes `docs/evidence/murk-benchmark.json` (`status: "NOT_RUN"` with reason when there is no key).
3. Chart component: IoU (y) versus turbidity (x) per target class, with the twin's unsafe-visibility threshold drawn as a vertical rule and the controller's slow-down band shaded, rendered from the JSON. NOT_RUN renders an honest empty state describing the experiment. Shown in scene 08 and reused by the Proof page (Task 9).
4. Tests: evaluation writes NOT_RUN without a key; with a mock transport writes numbers; chart renders both states.

## Task 8: Live run recorder and bundles

Files: new `backend/app/record.py`, `backend/app/main.py`, `package.json` script `record:live`, new `public/live-runs/README.md` (explains that bundles appear here only after a real recording), `lib/api/bundle.ts` (types plus loader), tests.

1. `GET /api/evidence/bundle/{missionId}` exports a bundle: `{schema: 1, kind: "RECORDED_LIVE_RUN", recordedAt, backendVersion, mission, plan, toolTimeline, transcript, captures: [{id, x, y, frameJpegBase64 (max 640 px), segmentations, quality}], report, workOrders, ask: [{question, answer, citations}], realcam: [...], executions: [...LIVE_META and CACHED_LIVE records only], totals: {liveCalls, cachedCalls, costUsd, meanLatencyMs}}`. Strip anything secret.
2. `npm run record:live` runs a curated live scenario through the real app in-process: the demo WAV through Voice Transcribe, Muse Spark planning, the twin-captured eval frames through the capture route (SAM), the summary, two Ask questions (one English, one Hindi), work orders, and one real-camera image if `--image path` is given. Hard budget `$0.30` for the run via the governor. Writes `public/live-runs/<yyyy-mm-dd>-<slug>.json` and updates `public/live-runs/index.json`. Without a key it exits non-zero with a clear message and writes nothing.
3. The frontend loader validates the schema and refuses bundles whose `kind` is not `RECORDED_LIVE_RUN` unless running tests with an explicit synthetic flag.
4. Tests: bundle shape, secret stripping, executions filtered to live classes, recorder refuses without a key.
